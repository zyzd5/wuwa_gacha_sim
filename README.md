# wuwa_gacha_sim

鸣潮（Wuthering Waves）**「角色活动唤取」限定 5★ 角色**抽卡模拟器，Rust 命令行程序。

给定抽卡次数 `N`，模拟这一段抽卡过程并输出统计：5★/4★ 产出、限定与歪的次数、
平均出金抽数、以及**大珊瑚（余波珊瑚）的完整结算明细**。

```console
$ cargo run --release -- -n 200 --seed 42
```

只模拟限定角色池，不含武器池、常驻池与新手池。

---

## 1. 编译与运行

需要 Rust 1.85 或更高（本项目使用 edition 2024，开发环境为 rustc 1.92）。

```bash
cargo build --release
./target/release/wuwa_gacha_sim -n 200 --seed 42
# 或者
cargo run --release -- -n 200 --seed 42
```

## 2. 命令行参数

| 参数 | 说明 |
| --- | --- |
| `-n, --pulls <N>` | **必填**，抽卡次数，`N >= 0` |
| `--seed <U64>` | 基准随机种子；不给则取系统时间，并打印实际使用的种子 |
| `--light` | 精简输出：每次模拟只打印一行「限定 / 常驻 5★ 数量」，与 `--repeat` 搭配使用 |
| `--repeat <K>` / `--loop <K>` | 独立重复模拟 `K` 次，`K >= 1`，默认 `1` |
| `--summary-only` | 只打印汇总与结束状态，不打印逐条明细 |
| `--detail` | 强制打印逐条明细（`N > 200` 时默认不打印） |
| `--no-color` | 关闭 ANSI 颜色 |

明细阈值：`N <= 200` **且** `--repeat 1` 时默认打印明细，否则默认只出汇总。
颜色在「stdout 是终端」且未设置环境变量 `NO_COLOR` 时才启用。

非法输入（负数、非数字、未知参数、缺少 `-n`、`--repeat 0`、`--detail` 与 `--summary-only` 同时给出）
一律打印错误到 `stderr` 并以**退出码 2** 结束；正常运行为 `0`。

程序**不接受任何初始状态参数**，也**没有续跑或状态持久化**：每次运行、每次重复
都从「5★/4★ 保底均为 0 抽、非大保底」的全新状态开始。

### 2.1 `--repeat`：重复模拟

`--repeat K` 把整场模拟独立跑 `K` 次，**不做任何跨次汇总**，就是把同一套统计重复输出 `K` 遍。

第 `i` 次（从 1 开始）使用的种子是 `基准种子 + i - 1`，因此：

- 每一次都是全新的保底状态，各次之间互不影响；
- 结果可复现：`--seed 42 --repeat 3` 的第 2 次，等价于单独跑 `--seed 43`。

完整模式下每次重复前会打印一行分节标题：

```
── 第 1/2 次  seed=42 ────────────────────────
```

#### 为什么「种子 +1」不会让各次结果趋同

这是个合理的担心：**如果 RNG 把种子直接当状态用**（比如朴素 LCG），
那么种子 42 和 43 会产生高度重叠的序列，`--repeat` 出来的结果就会假性一致。

ChaCha8 不会这样，原因有两层：

1. **u64 种子不直接当密钥。** `rand_core` 的 `seed_from_u64` 先用 PCG32 的输出函数
   把 u64 搅拌成 32 字节密钥（`state → state × MUL + INC` 再异或右移、循环移位）。
   种子 42 与 43 进去之后，中间状态相差的不是 1 而是 `MUL`（一个 64 位大奇数）。
   该函数的文档明确写着它「designed such that low Hamming Weight numbers like 0 and 1
   can be used and should still result in good, independent seeds」。
2. **ChaCha8 是密码学流密码。** 密钥变一位，8 轮 ARX 扩散后输出完全雪崩。

实测（`cargo run --release --example seed_quality`，26 万个 u64 样本）：

```
种子相差       +1 : 平均 Hamming 距离 31.9987 位   卡方 14.60 (df=9, 临界 16.92)  ✓
种子相差  +65_536 : 平均 Hamming 距离 32.0005 位   卡方  9.23 (df=9, 临界 16.92)  ✓
种子相差    +2^32 : 平均 Hamming 距离 32.0029 位   卡方 13.06 (df=9, 临界 16.92)  ✓
种子相差    +2^63 : 平均 Hamming 距离 31.9918 位   卡方  9.93 (df=9, 临界 16.92)  ✓
对照组（同一种子自比）: 平均 Hamming 距离 0.0000 位  ← 检验灵敏度确认
```

「+1」和「+2^63」的表现没有区别，都等同于随机。

模拟层再看一次（20000 次 × 200 抽，三种派生方式对比）：

```
派生方式                          均值     方差      范围    P(限定=0)
基准种子 + i （--repeat 的方式）   2.0545   0.7675   1..7      0.00%
大跨度种子 i × 黄金比常数          2.0663   0.7743   1..7      0.00%
单个主 RNG 派生                    2.0671   0.7665   1..7      0.00%

连续种子 vs 主 RNG 派生 的卡方: 5.08 (df=6, 临界 12.59)  ✓ 通过
```

均值彼此相差不到 0.7%，方差几乎相同。**结论：「+1」是安全的。**

> 顺带解释 `P(限定=0)` 为什么是 0：单次出金的间隔最多 80 抽，所以 200 抽里
> **至少**会出 2 个 5★，限定数不可能为 0。

需要注意的另一点：`--repeat` 派生出的是一串**确定性**序列，不是「真随机」。
「真随机」只体现在基准种子取自系统时间（或你手动指定的任意值）。
只要基准种子够任意，整组结果就够任意；而同一组种子永远可复现——这正是想要的取舍。

### 2.2 `--light`：精简输出

`--light` 每次模拟只输出一行，只含限定与常驻 5★ 的数量（外加该次使用的种子，便于复现）：

```console
$ ./target/release/wuwa_gacha_sim -n 200 --seed 42 --light --repeat 10
=== 鸣潮 · 角色活动唤取 模拟 · light ===
抽卡次数 : 200
基准种子 : 42
重复次数 : 10

#1    限定 1  常驻 1  seed=42
#2    限定 4  常驻 1  seed=43
#3    限定 5  常驻 0  seed=44
#4    限定 4  常驻 1  seed=45
#5    限定 1  常驻 2  seed=46
#6    限定 2  常驻 2  seed=47
#7    限定 2  常驻 1  seed=48
#8    限定 1  常驻 2  seed=49
#9    限定 1  常驻 2  seed=50
#10   限定 1  常驻 2  seed=51
```

计数排在前面、种子排在后面，这样不同位数的种子不会把前面的列推歪。
`--light` 下 `--detail` / `--summary-only` 没有意义（明细本来就不输出）。

**`--light` 不会改变随机流消耗**：它只影响渲染，同一个种子在 `--light` 与完整模式下
得到的计数完全一致。这一条有测试守着（`light_agrees_with_full_output_for_the_same_seed`）。

## 3. 概率模型

### 3.1 5★ 出率曲线

设 `n` = 距上次出 5★ 已抽的抽数 + 1（即本次是第 `n` 抽）：

```
p5(n) = 1.0                            if n >= 80
      = min(1.0, 0.008 + 0.06*(n-65))  if n >= 66
      = 0.008                          otherwise (n <= 65)
```

| n | 1 | 65 | 66 | 79 | 80 |
| --- | --- | --- | --- | --- | --- |
| `p5(n)` | 0.8% | 0.8% | 6.8% | 84.8% | 100% |

> **这不是官方公式。** 官方只公示了「基础 0.8% + 综合 1.8% + 至多 80 抽」三个数，
> 没有披露软保底曲线的形状。上面这条曲线是一个能**同时复现这三个数**的拟合模型
> （综合出率算出来是 1.8648%，与公示的 1.8% 相符）。

### 3.2 4★ 出率曲线

设 `pity4` = 已累计未出「4★ 或以上」内容的抽数：

```
p4(n) = 1.0     if n >= 10
      = 0.06    otherwise
```

本模拟器**不实现** 4★ 的 50/50、不实现 4★ 大保底、不拆分 UP / 非 UP，4★ 只按概率产出并计数。

**判定顺序与重置语义（关键）：**

1. 一次唤取只产出一个物品：先判 5★，未出 5★ 再判 4★，仍未出则产出 3★ 武器。
2. **产出 5★ 时把 `pity4` 归零**。官方措辞是「至多 10 次唤取必获得至少 1 个 4★ **或以上**内容」，
   5★ 同样满足这个保底条件，所以它也会重置 4★ 计数。
3. 产出 4★ 时 `pity4` 归零；否则 `pity4 += 1`。

> 第 2 条不是可有可无的细节。两种实现在 4★ 出率上相差 **0.64 个百分点**：
>
> | 实现 | 4★ 出率 |
> | --- | --- |
> | 5★ 重置 `pity4`（本项目采用） | **12.12%** |
> | 5★ 不重置 `pity4` | 12.76% |
>
> `src/tests.rs` 里的 `pity4_is_reset_by_five_star` 专门锁住这条语义，
> 大样本测试的 4★ 上界也卡在 12.5%，一旦漏实现就会测崩。

### 3.3 5★ 的 50/50 与大保底

- 非大保底状态下，5★ 有 **50%** 为 UP 限定角色、**50%** 为常驻 5★角色。
- 若出常驻（即「歪」），则**下一次** 5★ 必定为 UP 限定角色。
- 出金后保底计数归零，大保底标记相应更新。

## 4. 大珊瑚（余波珊瑚）结算

「大珊瑚」是社区俗称，游戏内货币名为**余波珊瑚**，8 个可兑换 1 抽。

| 产出 | 大珊瑚 | 构成 |
| --- | --- | --- |
| 5★ **限定**角色 | **+15** | 基础 15 |
| 5★ **常驻**角色（歪） | **+45** | 基础 15 **+ 歪补偿 30** |
| 4★ 内容 | **+8** | 基础 3 **+ 满共鸣链转化 5** |
| 3★ 武器 | **+0** | 走另一种货币「小珊瑚」，本程序不统计 |

因此恒有：

```
大珊瑚总量 == 限定5★数 × 15 + 常驻5★数 × 45 + 4★数 × 8
```

这条恒等式是**结构性成立**的（珊瑚只在 `Stats::record` 里按产出物品结算），
并有单元测试 `coral_identity_holds_over_a_large_run` 守着。

### 4.1 两条必须知晓的建模假设

1. **假设所有 4★ 角色均已满共鸣链**，故每个 4★ 一律按 8 计。
   真实规则里只有 **4★ 角色**满链后才给 8，**4★ 武器**始终只给 3。
   本模拟器不拆分 4★ 的角色/武器（见 3.2），因此这个假设会让大珊瑚总量**略微偏高**。
2. **不计算 5★ 的满命加成**。真实规则中 5★ 角色第 8 次及以后重复获得给 40；
   本模拟器不做角色重复计数，限定 5★ 一律按 15 计。

另外，3★ 武器产出的「小珊瑚」（残振珊瑚，70 个兑换 1 抽）**完全不统计、不输出**。

## 5. 统计口径

- **出金率** = 5★ 总数 ÷ 总抽数；**平均出金抽数** = 总抽数 ÷ 5★ 总数。
- **常驻 5★(歪)** 就是输掉 50/50 的次数，两者**恒为同一个数**：大保底状态下出金必定是限定，
  所以「拿到常驻 5★」与「输掉 50/50」互为充要条件。既然永远相同，只显示一行。
- 输出**不展示 3★ 武器数量**（它在实际中不产生任何有用资源）。
  程序内部仍在统计它，单元测试用它确认三档稀有度把总抽数分干净了。
- 除数为 0 时（如 `N = 0`）显示 `-`，不会出现 `NaN` / `inf`，也不会 panic。
- 明细行的 `#` 序号按事件发生顺序对 5★ 与 4★ 连续编号。
- 输出顺序固定为：汇总 → 大珊瑚明细 → 结束状态 → 与理论值对比 → **明细（最后）**。

## 6. 理论值

### 6.1 长期平稳值

模拟次数足够多之后收敛到的数值，也是大样本校验的断言基准。
5★ 部分为精确解析解；4★/3★ 与珊瑚为 2000 万抽参考模拟的实测值。

| 指标 | 理论值 |
| --- | --- |
| 5★ 综合出率 | 1.865% |
| 期望出金抽数 | 53.625 抽 |
| 限定 5★ 出率 | 1.243%（占 5★ 的 2/3），期望 80.44 抽/限定 |
| 常驻 5★ 出率 | 0.622%（占 5★ 的 1/3） |
| 65 抽内出金概率 | 40.67% |
| 5★ 分布 | P(X≤66)=44.7%、P(X≤70)=79.6%、P(X≤75)=99.3% |
| 4★ 出率 | 12.12%（期望 8.25 抽/4★） |
| 3★ 武器出率 | 86.01% |
| 大珊瑚 / 100 抽 | 143.6 |

三项出率之和恒为 100%：1.865% + 12.12% + 86.01% ≈ 100%。

### 6.2 从零保底起步的精确期望

**上面那些长期值不能直接乘抽数用。** 一次真实的抽卡是从「保底 0 抽」开始的，
前 65 抽享受不到软保底，所以短抽数的实际期望明显更低：

| 抽数 | E[5★] | E[限定] | E[4★] | 折算 5★ 率 |
| --- | --- | --- | --- | --- |
| 80 | 1.258 | 0.689 | 9.5 | 1.57% |
| 200 | **3.251** | **2.058** | 24.1 | 1.63% |
| 1000 | 18.248 | 12.054 | 121.0 | 1.82% |
| 2000 | 36.896 | 24.486 | 242.2 | 1.84% |
| 长期 | — | — | — | 1.865% |

200 抽时两者的差距不小：长期口径给 `200 × 1.865% = 3.73` 个 5★，
而真实期望只有 **3.25** 个；限定数的差距更大（2.49 vs 2.06，虚高 21%）。
拿长期口径去评价运气会**系统性地偏严**，让人误以为自己是非酋。

所以程序里的「与理论值对比」和所有 `[理论 …]` 标注都用**精确期望**，而不是长期率。
它由 `theory::expectations(pulls)` 动态规划求出：状态是
`(剩余抽数, pity5, 是否大保底, pity4)`，逆推该状态下的期望「限定 / 常驻 / 4★」数量。

- `pulls <= 2000`：直接递推，精确。
- `pulls > 2000`：只精确算 2000 步，其余用平稳期每抽增量线性外推
  （多算 100 步来估计该增量）。误差在 `1e-12` 量级。

实测交叉验证（`examples/seed_quality.rs`，20000 次独立模拟 × 200 抽）：

```
                        限定        常驻     5★ 合计         4★
精确 DP               2.0582     1.1928     3.2510    24.1308
实测（20000 次平均）   2.0545     1.1941     3.2485    24.1450
长期口径 抽数 × 出率    2.4864     1.2432     3.7296    24.2414
```

## 9. 可复现性

随机源是 `rand_chacha::ChaCha8Rng`，通过 `SeedableRng::seed_from_u64` 播种。

**没有**使用 `rand::rngs::StdRng`：它的算法不保证跨 rand 版本稳定，
一旦升级依赖，同一个种子就会给出不同结果。ChaCha8 的输出由算法规范
完全确定，与平台和版本无关。

`Cargo.toml` 里的依赖用 `=` 精确锁版本，且 `Cargo.lock` 已提交，
因此「同一 `--seed` 得到同一结果」是可靠的。
